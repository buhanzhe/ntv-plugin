# TVBox 站点加载排查（2026-11-24）

对用户当前配置逐项检查 50 个条目：49 个爬虫站点和 1 个广告提示项。Android 4.4.4 SM-G3608 / ARM32，Bro 1.8.3 / versionCode 12。以下为同一轮实机记录，单位毫秒。初始化、首页、推荐和首分类分别计时；首分类即使首页已有影片也单独测量，因此各列合计不是用户进入首页的耗时。没有验证每个站点的所有播放线路。

## 发现与调整

- “荐影”的首页与首分类各等待约 30 秒，返回空列表；“韩迷”的推荐约 9.2 秒，而首分类约 0.47 秒。“风云”的推荐约 1.6 秒，首分类约 5.2 秒且为空，固定把某一种接口排在前面会拖慢另一类站点。
- 首页返回分类后先呈现可操作的分类与搜索。Java/HTTP 站点的推荐和首分类使用最多两个独立后台会话，采用先返回的有效内容；离开页面取消并忽略迟到结果。JavaScript/Python 保持单会话顺序兜底，避免同一解释器并发修改状态。后台队列有界，不能无限增加请求。
- Java/HTTP 探测直接尝试目标接口；只有返回空内容或初始化依赖错误时补做首页初始化，减少重复首页请求。取消和网络错误不触发初始化重试。
- 最近 8 个首页可立即复用；成功的分类页与详情使用 2 分钟缓存，最多 24 项、合计约 100 万字符。空结果和错误不缓存，播放解析结果不缓存。筛选和页码进入缓存键，配置变化、网盘授权更新与站点操作会使缓存失效。
- 缓存页面直接呈现，播放前重新绑定正确站点。测试覆盖从其他站点返回缓存详情后仍使用正确播放源。

## 时限与实测范围

4.4 和 7.1 的本地定时样本均验证：分类先于 4 秒慢推荐可操作，推荐也能先于 4 秒慢分类出现；首屏约 0.1 秒、有效内容约 0.2–0.4 秒。重复分类/详情不再增加接口调用；迟到回包不会覆盖已切换的页面，授权失效测试没有更改真实凭据。实际 7.1 复测“韩迷”“风云”“儿童”，均取得内容；“儿童”首页在不同轮次出现 6–17 秒波动，仍受上游接口影响。不能将本地样本延迟作为全部第三方源的加载保证。

第三方 Java JAR 自建的网络客户端可能不响应取消，单次内部请求仍可能等待其自身超时。框架会限制后台并发和队列、忽略过期结果，无法替上游恢复失效接口。搜索型、推送型和授权操作型站点的空推荐不等于功能不可用。广告提示项在产品中直接显示，不会按爬虫执行。
