# v6 简化按需授权

日期：2026-11-26。版本 6，minSdk 14，379,864 字节。最终 JAR SHA-256：`ee2c52b1c8704f112df9601565f74985652ce2e104960f2ddeb18959115caecd`。独立探针校验并加载此 JAR，不覆盖正式 nTv。

- 删除侧栏“文件授权”及其中混合的六项操作；Android 5.0+ 只保留“添加文件夹”，直接进入系统目录选择器，已选目录显示在对应存储页。
- 点击本机目录后才请求所需读取权限。拒绝时就地显示“允许访问”“选择文件夹”和“返回”，不能继续请求时才提供设置入口。宿主未声明读取权限时可直接选择文件夹。
- SMB 的局域网权限只在扫描/连接时处理，不放入文件授权流程。媒体与局域网请求共用一个有时限的状态观察器；返回、切换来源或选目录会取消旧请求的恢复动作。
- 从设置返回重新检查。授权成功继续原操作，取消后不自动重新弹窗。新 API 仍由系统版本判断隔离，4.0.4 不出现新系统的授权入口。

设计依据：[Android 按功能请求权限](https://developer.android.com/training/permissions/requesting)、[系统目录选择器无需广泛存储权限](https://developer.android.com/training/data-storage/shared/documents-files)。

## 文件授权与遥控器

真实系统“选择目录”通过焦点与 D-pad 确定完成，系统返回持久树 URI，插件保存读取授权并记录目录。结束探针进程后，第二进程在 READ/WRITE AppOps 均受限时仍能打开该目录并播放。测试宿主目录 Intent 与现有宿主一样只添加 READ 标志，不通过伪造 URI 绕过系统选择器。

授权面板隐藏后台焦点；目录返回恢复父目录和原选中卡片，网格左边缘进入侧栏、向右回到网格。播放菜单键聚焦按钮，确定操作当前按钮，左右跳转 10 秒，前后台暂停/恢复，返回释放播放器。系统解码得到 640×360、时钟推进超过 2 秒，Android 9 同时收到原生 `MEDIA_INFO_VIDEO_RENDERING_START` 回调。

模拟器限制：该 ROM 将存储权限列为安装时授权，`pm revoke` 不产生真实运行时拒绝/允许对话框，因此本轮用 AppOps 验证访问受限与设置返回后重检。系统即使报告允许，该探针的原始共享存储路径仍不可读；插件给出明确授权提示，真实系统目录授权路径可正常浏览、播放和跨进程保留。不能据此宣称所有电视 ROM 的运行时对话框已验收。

- 背景 256×144，四类图标各 224×196；RGBA 像素缓存总计 849,920 字节（约 0.81 MiB），按需生成并跨卡片复用。
- 目录中 600 个扩展名为 .mp4 的测试文件，仅实例化 6 张可见卡片；不扫描整个目录生成视频封面。
- 20 次跨位置浏览时，16ms 主线程心跳的间隔 P95 为 55ms（58 个样本）。
- 原尺寸离屏软件绘制 24 次（预热 4 次后），耗时 P95 为 42.79ms。
- 探针进程 PSS 为 13,188 KiB；当次 Java 堆已用约 17,683 KiB。PSS 与堆统计口径不同，不应相加。
- 目录页没有动画、实时模糊或持续刷新；绘制复用材质、位图与裁切好的文字。旧系统 SMB 扫描使用 8 个工作线程。
- 加载转圈只在可见时运行，API 15 使用约 32ms 间隔；控制层隐藏/后台时停止时钟刷新。

这些数值是该设备当次负载下的队列响应与离屏软件绘制观测，并非显示帧率、硬件渲染时间或无卡顿承诺，未用未经控制的两次测试宣称加速百分比。
